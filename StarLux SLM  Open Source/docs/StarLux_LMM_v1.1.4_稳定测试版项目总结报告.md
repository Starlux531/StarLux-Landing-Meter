# StarLux LMM v1.1.4 稳定测试版项目总结与 v1.2.0 继承报告

- 项目：StarLux Landing Meter / StarLux LMM
- 平台：X-Plane 12 + FlyWithLua NG+
- 总结基线：v1.1 正式版
- 当前锚点：v1.1.4 稳定测试版
- 归档日期：2026-08-23
- 下一计划版本：v1.2.0（操纵曲线与分析器多皮肤）

## 一、结论摘要

v1.1.4 已经从 v1.1 的“落地结果记录器”发展为一套较完整的本地落地复盘系统。当前版本同时包含接地 FPM、接地载荷 G、弹跳、100 ft 拉平轨迹、天气与道面、真实跑道与触地点、中心线评分、双语 TXT、游戏内记录管理和独立网页分析器。

本阶段最重要的成果不是继续增加更多中间量，而是重新明确了三条原则：

1. FPM 以 AGL 几何下降率作为跨机模锚点，在物理垂直速度与 VVI 中择近，必要时直接采用 AGL，不再固定偏好某一种机模数据。
2. G 以第一次接触后的固定 160 ms 稳健载荷为主值，冲量与物理平均载荷只负责复核，不再反向抬高最终结果。
3. 跑道只能由 apt.dat 真实几何、触地点坐标和飞行方向共同确认；识别失败时不使用磁航向猜测。

因此，v1.1.4 适合作为 v1.2.0 及后续版本的功能锚点。后续“操纵曲线”应作为新的独立展示层接入，不能重新扰动已经稳定下来的 FPM、G、跑道识别、评分和旧日志兼容链。

## 二、当前插件开发状态

### 2.1 当前可用能力

插件侧已经具备以下完整链路：

- 进近阶段使用固定容量缓冲区采样，避免持续创建临时表。
- 首次接地后分阶段完成 FPM、G、弹跳、评分、机场跑道解析和日志写入，避免把全部工作压在触地关键帧。
- 自动生成 UTF-8 中文或英文 TXT，文件名带 `_CN` / `_EN` 标记。
- FlyWithLua 设置窗口和落地记录管理器固定使用英文，避免 ImGui 中文字形乱码；宏菜单保留“打开设置/Open Setting”和“落地记录/Landing Record”双语入口。
- 数据输出设置统一命名为 `Data output language`，中文 TXT、落地弹窗和分析网页继续跟随该设置。
- 回放期间暂停采样、触地识别和日志生成，退出回放后等待下一次真实进近。
- 支持立即显示、低于 30 kt、停稳 10 秒和不自动显示等落地弹窗策略，并保留纯净模式。

阅读器侧已经具备以下复盘能力：

- 同时读取中文、英文以及 v1.1–v1.1.4 的历史日志字段。
- 展示并对比关键落地数据、相对风、姿态仪、迎角侧视图、真实跑道和准确触地点。
- 100 ft 图表支持轨迹 FPM、VVI、物理 FPM、RA、IAS、GS、Pitch、AoA 和 Roll 多参数叠加。
- 主日志使用实线，对比日志使用同色虚线；风向、姿态仪和迎角图也支持双记录叠加。
- 支持深色与浅色主题，并针对浅色背景重新处理文字、图形、参考线和事件标签对比度。
- 跑道使用固定可读视角，保持入口、接地点和剩余距离的真实纵向比例；跑道长短通过标线与距离密度表达。

### 2.2 当前评分体系

FPM 与 G 仍分别分档，然后取更严重的等级：

| 等级 | FPM | G |
|---|---:|---:|
| Nice | ≤ 100 fpm | ≤ 1.20 G |
| Stable | ≤ 250 fpm | ≤ 1.50 G |
| Attention | ≤ 300 fpm | ≤ 1.80 G |
| UNSTABLE | > 300 fpm | > 1.80 G |

精准跑道识别成功后，再叠加中心线规则：

- 偏离中心线超过 7 m：在非红等级内降一级，并标记偏离距离。
- 偏离中心线超过 15 m：直接标记为 UNSTABLE。

弹跳继续使用既定降级规则。拉平曲率、冲量闭合误差、7.5° 通用尾擦参考线均用于复盘，不直接参与评分。

## 三、v1.1 到 v1.1.4 的总体变化

### 3.1 总览对比

| 维度 | v1.1 正式版 | v1.1.4 稳定测试版 |
|---|---|---|
| FPM 主逻辑 | 三链两两差值 ≤ 60 fpm 时采用物理值，否则由 VVI 接管 | AGL Theil-Sen 几何下降率作为锚点；物理/VVI 与 AGL 差值 ≤ 30 fpm时择近，否则采用 AGL |
| 物理 FPM 窗口 | 5 ft 以下 250 ms 物理 P25 为主要候选 | 优先接地前 100 ms 离地物理速度中位数，250 ms P25 仅在短窗缺样时备用 |
| G 主逻辑 | 全段 P75 与滑动 160 ms 局部包络按分支取较大值 | 第一次接触后固定 160 ms P75 为主；全段 P75 只在缺样时备用 |
| 冲量作用 | 参与可信度、分支和结果约束 | 统一按 `(G-1)g` 复核物理闭合，不再抬高主 G |
| 跑道信息 | 只记录最近机场，不能可靠输出真实跑道与触地点 | 按 scenery_packs.ini 优先级读取 apt.dat，输出真实跑道、触地点、中心线偏差和跑道属性 |
| 密集机场 | 只依赖单个最近机场参考点 | 低频发现并缓存相邻机场；主机场几何失败后静默使用严格包络复核 |
| 100 ft 轨迹 | 10 Hz 原始采样、0.5 秒网页聚合，使用地形 AGL | 140 ft 提前采样、接地参考高度校准、机场标高基准优先、0.25 秒网页聚合 |
| 网页上下文 | 主要是数字卡片与多参数曲线 | 默认展示风向、姿态仪、迎角、真实跑道和触地点，并支持这些项目的对比 |
| 主题与可读性 | 单一深色体系，局部区域字号较紧 | 深/浅主题、整体 UI 放大、绘图区和 Canvas 标签同步增强 |
| 输出语言 | v1.1 以中文为主，菜单中文化 | TXT/弹窗/网页跟随 Data output language；ImGui 固定英文、宏菜单双语 |
| 日志结构 | 保留较多算法中间量与可信度路径 | 普通日志只保留明确采用源、关键候选、样本质量和复核结论 |
| 数据读取 | 20 个直接 XPLM DataRef | 23 个直接 XPLM DataRef；新增本地水平速度向量与 MSL 高度，不保留实验性起落架数组 |

从代码规模看，Lua 由 4,731 行增长至 6,479 行，阅读器由 804 行增长至 1,259 行。增长主要来自跑道解析、双语兼容、轨迹校准、阅读器仪表化和本地报告管理，而不是增加持续运行的高频算法。代码行数只用于说明项目范围变化，不代表算法质量。

### 3.2 v1.1.1：语言与交付体系形成

v1.1.1 把“界面语言”和“数据输出语言”拆开：FlyWithLua ImGui 固定英文以绕开中文字形问题，TXT、弹窗和网页可以输出中文或英文。CFG 使用 `document_language`，并兼容旧 `interface_language`。同时加入纯净模式、国内版/国际版初始设置和 `_CN` / `_EN` 文件名后缀。

这一阶段奠定了后续所有日志兼容工作的基础：阅读器不能只识别一种语言，也不能假定某个版本只有一套字段。

### 3.3 v1.1.2：重着陆修复与实验收敛

v1.1.2 针对较大下降率时 250 ms 物理窗口容易包含拉平前段、导致结果偏重的问题，引入更短的离地物理速度复核。更重要的是，未发布的起落架受力、压缩量、压缩率数组和接触探针被完整移除，没有把未经充分验证的机模相关实验带入稳定主线。

这一阶段形成了一个延续到 v1.1.4 的工程决定：优先改进已有通用测量链，不依赖每个机模都可能不同的起落架内部数据。

### 3.4 v1.1.3：真实跑道与阅读器仪表化

v1.1.3 是功能范围扩展最大的一次迭代。插件开始读取 scenery_packs.ini 和 apt.dat，使用真实跑道端点、触地坐标与触地地速向量进行几何匹配，并把跑道长度、宽度、双端编号、入口内移、防吹坪、标线、TDZ/REIL、中线灯、边灯和有符号中心线偏差写入报告。

为避免大型 Global Airports 文件在触地后才扫描而超时，跑道数据改在 5000–100 ft 的下降进近阶段分帧预读。v1.1.4 又在这一基础上加入密集机场的相邻机场缓存：最近机场的跑道不匹配时，才对已缓存机场使用同一严格包络复核，不放宽容差、不猜跑道。

阅读器同期完成仪表化：取消隐藏的“着陆上下文详情”，默认显示风向、接地姿态和跑道。横滚与俯仰合并为移动地平线姿态仪；迎角保留侧视机翼和气流，并加入 7.5° 通用尾擦俯仰参考；真实跑道使用固定可读视角绘制，100 ft 图底部加入跑道入口—接地事件带。

### 3.5 v1.1.4：FPM/G 主链重建与日志减负

多机模测试证明，物理 FPM、VVI 和轨迹 FPM 都无法单独覆盖所有飞机。v1.1.4 因此不再设置固定优先级，而是把 5 ft 以下 AGL Theil-Sen 几何下降率作为锚点：

1. 计算接地前 100 ms 离地物理速度中位数；缺样时才用 250 ms 物理 P25。
2. 计算同阶段 VVI 候选。
3. 计算 AGL 几何锚点。
4. 物理值或 VVI 与 AGL 的差值不超过 30 fpm 时，采用更接近 AGL 的候选。
5. 两个有效候选均偏离 AGL 超过 30 fpm 时，直接采用 AGL。
6. AGL 缺样时才依次回退到物理候选和 VVI。

G 值也从“寻找压缩段内较大值”改为“测量第一次承载”：主值固定取第一次接触后 160 ms 的 P75。物理平均载荷使用 `1 + Δv/(g·Δt)`，冲量使用 `(G-1)g`；两者只用于闭合复核。这样避免滑动窗口不断寻找最大载荷造成系统性上偏，也避免把重力基准重复或遗漏。

普通 TXT 同步清理了容易误解的中间峰值、分支置信度和重复推导，只保留最终 FPM/G、明确采用源、关键候选、样本质量与复核结论。详细数学日志仍可在需要时启用，阅读器继续兼容旧字段。

## 四、当前关键算法决定

以下决定应被视为 v1.1.4 锚点的一部分，后续版本除非有新的跨机模证据，不应顺手改动：

1. **AGL 是 FPM 锚点，不是无条件唯一数据源。** 物理值和 VVI仍可在与 AGL 接近时胜出。
2. **30 fpm 是当前候选—锚点差值上限。** 它替代了 v1.1 的三链两两 60 fpm 一致性规则。
3. **G 与 FPM 不互相估算主值。** G 来自载荷窗口，FPM 只在 G 缺样备用路径中提供上限保护。
4. **冲量只复核，不参与抬高评分结果。** 闭合偏差可以提示样本问题，但不能自动制造更大的 G。
5. **跑道必须有几何证据。** 最近机场参考点只负责提供快速入口，最终跑道必须由真实跑道包络和飞行向量确认。
6. **中心线偏差是独立评分维度。** 它在 FPM/G 基础等级完成后再降级，不与其他项目平均抵消。
7. **阅读器负责解释，不改写历史结果。** 旧日志高度校准只修正绘图，不改 FPM、姿态、评分或原始 TXT。
8. **7.5° 是通用视觉参考，不是机型限制。** 不得把它直接用作尾擦判定或评分阈值。

## 五、性能与兼容性现状

### 5.1 性能控制

- 高频数据保存在预分配环形缓冲区中。
- 轨迹按固定间隔采样，分析和日志写入分阶段执行。
- apt.dat 使用分块读取；相邻机场候选会在已有顺序扫描中顺带缓存。
- 最近机场中心查询保持低频，相邻方向探测只在移动超过约 2 km 或间隔 30 秒后执行。
- 进近灯与未采用的自动标牌字段不再读取或跨阶段保存。
- 未发布的起落架接触数组实验已经移除，不增加正常飞行阶段负担。

### 5.2 兼容性承诺

- 继续支持 v1.1–v1.1.3 的旧 TXT 字段。
- 继续支持中文/英文两套报告字段和文件名。
- 继续支持旧 0.5 秒聚合轨迹；新日志使用 0.25 秒网页显示点。
- CFG 保留 `document_language`，并维持现有弹窗、位置、布局、透明度和数学日志设置。
- 不要求联网，不依赖外部机场服务或在线数据库。

## 六、已经解决的主要问题

- 长行程起落架机模中物理 FPM 与实际下降趋势不一致。
- 较重落地时宽物理窗口把拉平前段带入结果，造成 FPM 偏大。
- 某些轻落地或大型机中物理 FPM、VVI 与 AGL 的固定优先级失真。
- G 局部窗口滑动寻找最大值造成结果系统性偏高。
- 冲量复算遗漏或错误处理 1.0 G 重力基准。
- 100 ft 轨迹在接地末尾被强制跳到 0 ft，形成明显截断。
- 海岸、悬崖或高架跑道上地形 AGL 突变造成高度轨迹缺口。
- 大型 apt.dat 触地后扫描超时，无法输出跑道。
- 南苑/大兴一类密集机场只选择最近参考点，导致正确跑道不在主机场几何内。
- 浅色主题中文字、曲线、姿态和跑道事件与背景混在一起。
- FlyWithLua ImGui 中文标签缺少字体时出现乱码。

## 七、当前仍然存在的边界

v1.1.4 被定义为“稳定测试版”，不等于已经覆盖所有飞机、插件组合和机场数据：

- FPM 仍依赖模拟器提供的 AGL、物理速度和 VVI 样本质量；三者全部缺样或时间轴异常时只能进入备用路径。
- G 是通用落地复盘值，不是机型起落架载荷、结构载荷或维修判定。
- 跑道识别依赖本地 scenery_packs.ini 与 apt.dat；机场数据缺失、重复或几何相互重叠时会拒绝猜测。
- 相邻机场候选必须在进近预读阶段被发现或缓存；极短的保存进近、瞬移或异常时间跳转可能压缩预读时间。
- 反复本场训练与读取机模保存状态需要继续覆盖不同机模的重置行为，尤其要防止上一轮缓存、回放状态和触地任务污染下一轮。
- 7.5° 尾擦参考不代表 A339、B738、A20N 或其他具体机型的实际尾擦限制。
- 当前尚未采集或显示操纵输入/控制面响应曲线。

## 八、验证覆盖与可信程度

本阶段已经使用 B738、A20N、A339 等不同机模的多份真实落地日志反复检查轻落地、较重落地、轨迹末端、AGL 跳变、跑道绘制和网页显示。测试机场包含普通民航机场、海岸/复杂地形机场以及紧邻军民机场场景。

这些样本足以证明 v1.1.4 相比 v1.1 的设计方向更稳健，也能复现并修复已知问题，但不能替代更大规模的回归矩阵。后续修改应至少重复以下组合：

- B738、A20N/A320 系、A339 或其他长行程起落架机型。
- 轻落地、正常落地、较重落地、弹跳、偏中心线。
- 普通机场、超长跑道、海岸/高架机场、密集机场、非 ICAO 本地机场编号。
- 连续本场训练、复飞后再落地、回放、保存状态直接载入进近。
- 中文/英文 TXT、深/浅主题、单日志/双日志对比。

## 九、v1.2.0“操纵曲线”继承建议

### 9.1 功能边界

v1.2.0 首阶段建议只做“记录与解释”，不把操纵曲线纳入评分。这样可以先建立不同机模之间的数据语义与可视化经验，避免尚未统一的操纵输入反过来影响 v1.1.4 的落地评级。

开始实现前需要明确：

1. 曲线记录的是驾驶员指令、实际控制面偏转，还是两者同时记录。
2. Pitch/Roll/Yaw 使用归一化比例、角度还是双单位展示。
3. 电传飞机、机械操纵飞机和机模自定义 DataRef 如何区分。
4. 采样窗口采用 140 ft 预采样后的 100 ft 区间，还是扩展到更早进近和接地后滑跑。
5. 是否需要滤波；若需要，原始值必须保留，滤波仅用于显示。

### 9.2 推荐接入位置

- **采样层：** 扩展现有预分配 `flare_trace` 槽位或增加独立固定容量缓冲区，不在每帧创建新表。
- **日志层：** 为新轨迹列使用明确、可选的中英文字段；旧日志缺少这些列时阅读器应正常工作。
- **阅读器层：** 复用现有多参数开关、单位分组、悬停读数和主/对比实虚线体系。
- **时间轴：** 与 RA、GS、Pitch、AoA、Roll 和跑道入口/接地事件共享同一 T+ 时间轴，避免产生第二套无法对齐的图表。
- **评分层：** v1.2.0 初期保持完全隔离，只有在积累跨机模数据并形成明确规则后才讨论评分。

### 9.3 性能与回归要求

- 新增 DataRef 数量应明确列出，并优先使用已有直接 XPLM 句柄体系。
- 先测量 10 Hz 是否足够表达操纵变化；如需更高频率，应单独评估内存、TXT 体积和网页绘图成本。
- 不得恢复已经移除的逐帧临时表、起落架接触探针或无用途数据读取。
- 新列不能改变现有 FPM、G、弹跳、中心线和跑道识别的计算顺序。
- 必须验证无操纵字段的 v1.1–v1.1.4 日志仍可载入和对比。

### 9.4 建议验收标准

## 十一、最终判断

v1.1 的核心贡献是建立三链 FPM、局部 G 包络、回放隔离和多参数阅读器；v1.1.4 的核心贡献则是把这些能力收敛成更清晰、更通用、可跨机模复核的体系，并补齐真实跑道、中心线、轨迹校准、双语输出和仪表化阅读器。

当前版本已经具备作为后续开发锚点的条件。v1.2.0 应把“操纵曲线”作为新的可选观测维度接入，并为分析器提供多种皮肤和显示色调，而不是重新打开 v1.1.4 已经收敛的接地算法。只要坚持数据层可选、阅读器兼容、评分隔离和固定缓冲区四项原则，新功能可以在不破坏稳定主线的前提下逐步扩展。
